# 生产安全清单

[文档首页](../README.md) · [设备接入与认证协议](AUTHENTICATION.md)

## 上线前：先确认谁能看到什么

- **监控数据默认公开。** 匿名访问者可以查看概览、主机详情和实时流；GitHub OAuth 保护管理功能。白名单中每个 GitHub 用户都是管理员。若监控数据不能公开，应在网络入口限制整个站点的访问，并为 Agent 保留受控的上报路径。
- **生产配置必须完整。** `publicUrl` 使用外部 HTTPS 源（无路径、查询或片段），填写 `github.clientId`、`github.clientSecret` 和非空的 `github.allowedUsers`。缺少必填项时服务拒绝启动；不要用 `insecureDevelopment` 绕过检查。
- **回环开发不是生产方案。** 开发模式仅允许显式回环 IP 监听；不配置 OAuth 时允许匿名管理。不要转发该端口，不要对外暴露 Vite 或 Vitest 开发服务。

## 反向代理

- 在受信任的代理终止 TLS，HTTP 重定向到 HTTPS；确认 HTTPS 正常后再启用 HSTS。后端监听端口不能直接暴露给不可信网络。
- 保留与 `publicUrl` 一致的 Host（含非默认端口）；`/report` 转发 WebSocket Upgrade 和 `X-Agent-Public-Key`，`/events` 关闭响应缓冲以便实时推送。不要让 CDN 缓存标记为 `no-store` 的响应。
- `trustedProxies` 仅填写实际代理的 IP/CIDR，由代理正确追加真实来源地址。否则每 IP 限额可能由所有客户端共享。健康探针使用 `GET /healthz`，这个路径不返回业务数据。

## 运行时限制与排查

| 现象 | 先检查 |
| --- | --- |
| 管理写请求被拒绝 | 是否有有效管理员会话、是否同源；退出登录仅接受 POST。OAuth state 短期有效、单次使用、绑定浏览器，并受容量和速率限制。 |
| 私网通知地址不可用 | 通知目标从解析到实际连接都必须是公网地址；不跟随重定向，不使用环境变量中的出站代理。请改用可信公网通知端点。 |
| Agent 连接或采样被拒绝 | 生产使用 WSS 并验证服务端证书。区分连接尝试限流与每台主机的消息限额（1 MiB/条、120 条/分钟）；避免空闲超时。校准设备时钟：采样时间与服务端相差不能超过 5 分钟，零值取服务端时间；最后在线时间按服务端收件时间计算。 |
| 大范围查询或实时订阅失败 | 用量查询有时间戳、7 天窗口、10,000 点及查询时限约束；SSE 最多全局 256 条、每来源 IP 8 条连接，并设写入期限。入口仍应设置合理连接限制。 |

## 凭据泄露或主机失陷

1. 待注册主机的安装命令包含短期凭据，持有者可能抢先绑定。不要分享截图、终端历史或剪贴板。未绑定时在**原主机记录**刷新凭据，旧凭据立即失效。
2. 已绑定时不能用新凭据覆盖公钥。公钥可公开，复制私钥则能冒充 Agent。隔离失陷主机并备份数据，再按[设备接入说明](AUTHENTICATION.md)用新私钥重新接入。**删除主机会断开连接并删除全部层级的历史，不可撤销。**
3. 限制配置、数据库、备份和每台 Agent 私钥的文件权限。旧实例若曾未授权暴露，应更换可能泄露且仍有效的通知密钥等凭据；升级不能收回已经泄露的副本。
4. 使用可信 Agent release 及下载代理。同源校验清单能发现损坏，不能独立验证发布者。更新前后端依赖（含开发依赖）时，重新构建嵌入资源，验证步骤见[测试与验收](TESTING.md)。
